**6. Isolation**
From steam.nix source: `pkgs.steam` is a `buildFHSEnv` compatibility namespace (bind-mounts an FHS-shaped tree for Proton/Windows binaries) — **not** a security sandbox; it doesn't restrict network/filesystem/device access by default. The only privilege-escalation path in the module is opt-in: setuid `bwrap` (only if `gamescopeSession.enable && gamescope.capSysNice`) and a `cap_sys_nice` wrapper for gamescope itself (`capSysNice`, default false). Leaving both off keeps things to unprivileged user-namespace bubblewrap. No authoritative documented recipe was found for running Steam as a second unprivileged user sharing the current GNOME/Wayland session's display and audio — reasoning from socket scoping: both Wayland (`$XDG_RUNTIME_DIR/wayland-0`) and PipeWire (`.../pipewire-0`) sockets live under the logged-in user's runtime dir with no formal per-connection ACL, so sharing them with a second UID requires manual bind-mount/chmod hacks that are fragile and let that second user screenshot/inject input into your session — self-defeating for isolation. GPU nodes (`/dev/dri/*`, `/dev/nvidia*`) aren't the blocker (group/world accessible); the socket sharing is.
- **(a) Always-on module**: simplest, uses the live session's sockets/GPU with zero extra plumbing. Con: shares the full operator account/session at all times, largest constant blast radius.
- **(b) `specialisation`**: separate boot entry with the gaming module enabled, base config untouched otherwise; declarative, easy to add/remove. Con: isolation is only temporal (absent from default boot) — once booted into it, same user/session model, no runtime containment; requires a reboot to toggle.
- **(c) Separate user**: strongest filesystem/credential isolation in theory, but on the *same* GNOME/Wayland session the display/audio sharing needed is unsupported and self-defeating; only makes sense with its own login seat (separate greetd session), a materially bigger lift.
- Given the stated goals, (a) with `capSysNice` and all `openFirewall` sub-options left at their false defaults is the pragmatic baseline; (b) is a reasonable middle ground for keeping gaming absent from the default boot entry.

**7. Firewall**
All three sub-options default **false** (opt-in, matching the requirement): `remotePlay.openFirewall` → UDP 27036 + TCP 27036 + UDP 27031–27035; `localNetworkGameTransfers.openFirewall` → UDP 27036 + TCP 27040; `dedicatedServer.openFirewall` → TCP 27015 + UDP 27015. **Safe to leave all closed for single-player use** — Steam's store/download/cloud-save/friends traffic is outbound-only; no inbound rule from this module is needed to install or play single-player games via Proton. Only flip `remotePlay` for streaming to another device, `localNetworkGameTransfers` for LAN transfers between your own machines, `dedicatedServer` for hosting a Source-engine server.

## Recommended module shape
A thin, nixpkgs-only NixOS module (no extra flake inputs needed for the core ask) that turns on `programs.steam.enable`, sets `programs.steam.extraCompatPackages = [ pkgs.proton-ge-bin ]`, `programs.steam.protontricks.enable = true`, and `programs.gamescope.enable = true` with `capSysNice` left at its default `false` unless the operator specifically needs gamescope self-renicing; enables `programs.gamemode.enable`, installs `mangohud` via `environment.systemPackages` or `extraPackages`, and gates `hardware.xone.enable`/`hardware.xpadneo.enable` behind operator toggles (steam-hardware is forced on automatically). Launchers (`heroic`, `lutris`, `bottles`) go in `environment.systemPackages`, each independently toggleable. All three `programs.steam.*.openFirewall` options should default `false` and be exposed as explicit module options the operator flips per-need. Suggested option surface: `gaming.enable`, `gaming.gamescope.capSysNice` (default false), `gaming.controllers.xone`/`.xpadneo` (default false), `gaming.launchers.{heroic,lutris,bottles}` (default false each), `gaming.firewall.{remotePlay,dedicatedServer,localNetworkTransfers}` (default false each), `gaming.lowLatencyAudio.enable` (only pull in nix-gaming's `pipewireLowLatency` if this is turned on).

- `steam`/`bottles` `.version` non-resolution is a nixpkgs eval quirk, not a build/security problem — confirmed both packages build.
