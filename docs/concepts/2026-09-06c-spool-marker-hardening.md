# Concept 2026-09-06c — seat-spool refuses a marker that is not a plain file before it unlinks

**Class:** seat / robustness. **Status:** parked (found by the judge panel reviewing `docs/superpowers/plans/2026-09-06-seat-driver.md`'s SD6 section; not folded into that plan's rule 2, which is dispatched as judged — see the judgement file `docs/reviews/plan-judgements/2026-09-06-seat-driver.md`, errata #13). **Origin:** SD6's spool directory `/var/lib/seat/spool` is `0730 root users` — the operator's group may create entries in it but not list them. `seat-spool`'s per-entry contract validates the entry NAME against `^\d{8}-\d{6}-[0-9a-f]{6}$` and then calls `os.unlink()` on it unconditionally; nothing in the plan's rule 2 checks that the entry is a regular file first. A directory (or a symlink) whose name happens to match the id pattern makes `os.unlink` raise `IsADirectoryError`, which today has no named handler — the exception would escape the per-marker loop and abort the run before any later marker in the same directory listing is processed.

**Idea.** Add a `not-a-file` refusal code, checked before every other validation and before the unlink: `os.path.isfile(entry) and not os.path.islink(entry)`, else `refused <id>: not-a-file` and `continue` (no unlink attempted on the offending entry — leaving it for the operator to clear by hand, since root owns the directory). Pair it with wrapping the unlink itself (`try/except OSError`) so a still-possible race (the entry vanishes between the `isfile` check and the unlink) degrades to a logged `unlink-failed` line rather than an uncaught exception, and do the same around the `subprocess.run(["systemctl", "start", ...])` call so a bad `--systemctl` path degrades to `could not exec systemctl for <id>` instead of killing the loop. The fixture that proves it: a directory marker sitting beside a valid file marker in the same spool listing — the valid one must still start.

**Payoff.** Closes a fail-open path in the one host-side actor that starts `seat@` instances as root: today a single malformed marker (created by mistake, or by a future caller that writes a directory instead of a file) can silently stop the spool from processing every marker queued after it in that `os.scandir()` pass, with no operator-visible signal beyond "jobs stopped starting." The fix is three small, independently testable changes (a refusal code, two `try/except OSError` wraps) with no schema or interface change to `seat-submit` or the units.

**Dependencies.** Applies directly on top of SD6 (`pkgs/seat/seat-spool.py`, `tests/seat/test_seat_spool.py`) once that task lands; no other task in the seat-driver plan touches this file. Independent of SD1–SD5, SD7–SD11.

**Earliest landing.** XS, as a fix-round or a small follow-up task once SD6 is on main; does not block the seat-driver plan's own wave 2 (SD6 dispatches as judged, without this hardening) or anything downstream of it.
