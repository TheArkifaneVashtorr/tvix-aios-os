## Findings

- **major** `tests/evidence/test_claims.py:62` — vacuous-test: `open_gaps` is a named Interface of E2 — "open_gaps(rows) -> list[dict] (sorted by `opened`, then id)" — and `evidence bundle` (E9) is specified to read the claims file through it, but no test can observe the ordering. The GOOD fixture contains exactly one gap, so test_good_file_validates_and_open_gaps_sorted asserts `== ["effort-policy-n1"]`, a one-element list. Replacing the sort key with `key=lambda r: 0, reverse=True` leaves the suite fully green ("7 passed"). The test's own name claims coverage it does not have. The block is the plan's verbatim test text, so the defect originates in the plan — but "a load-bearing test counts only once it has been shown to fail" is a repo rule, and adding a case is an addition, not a deviation from `touches`. **Fix:** Add a second gap to GOOD with an earlier `opened` (e.g. id "aaa-earlier-gap", opened 2026-09-03, plus the required owner/review_by/closes_by) and a third sharing `opened` with effort-policy-n1 but sorting earlier by id; assert the full three-element order from claims.open_gaps. Show it red by neutralising the sort key, then green. No production-code change.
- **minor** `pkgs/evidence/claims.py:26` — The evidence revision's lower bound (`@[0-9a-f]{7,40}`) is unpinned: widening it to `{1,40}` keeps every test green, so `evidence = "check:lint@f …"` would be accepted as a verified claim. That floor is the only thing separating a real abbreviated commit id from a typo. **Fix:** In test_verified_evidence_must_be_check_or_operator_form add a negative case `evidence = "check:unit@abc tests/…"` and assert the "must start with" error fires. Implementation unchanged.
- **minor** `docs/ledger/claims.toml:40` — All 21 gaps carry `opened = 2026-09-05`, including items the board records as open earlier (docs/OPERATIONS.md:53-58 lists the D5 activity export, the S12 commit-metadata decision and the xhigh/medium item as operator carry-overs, and the xhigh backup file is named `…settings.yaml.bak-2026-09-04-xhigh`). The implementer's transcript says it "picked plausible dates" because the plan's seed table gave none. `opened` is the primary sort key of open_gaps, so a uniform value makes that ordering degenerate on the real file and weakens the age signal `evidence bundle` will print. **Fix:** Backdate the carry-over gaps to the day the board first recorded them (2026-09-04 for d5-activity-export, s12-commit-metadata-decision, xhigh-restore-or-keep-medium, m3-comfy-angle-aimdo; keep 2026-09-05 for the ones the environment review opened), or state in the file header (docs/ledger/claims.toml:1-5) that `opened` means "first recorded in the claims file".
- **minor** `docs/ledger/claims.toml:164` — The environment-review finding ids the plan's seed table attached to eight gaps (invariants-1, invariants-3, invariants-5, invariants-6, hygiene-1, hygiene-2, r2-2-5, r2-4-1/r2-4-2) appear nowhere in the file, so a gap cannot be traced back to docs/reviews/2026-09-05-environment-review.md. Defensible reading — in the plan's table the quoted span is the closes_by value and the `review …:` prefix is a provenance annotation outside it, and the implementer preserved the quoted span exactly — but the provenance is lost. **Fix:** Either prefix those closes_by values with `review <id>: ` as the table renders them, or (cleaner, and no schema change since the validator ignores unknown keys) add `source = "review invariants-1"` and friends to the eight rows.
