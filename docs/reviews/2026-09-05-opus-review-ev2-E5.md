## Findings

- **minor** `pkgs/helm/collect.py:8` — The module docstring still calls docs/superpowers/specs/2026-09-02-helm-design.md "the normative tile rules and the drift algorithm", but that spec is now stale: its table row (spec line 104) still reads `flake check | /var/lib/helm/flake-check.json | ok and rev == repo HEAD and age < 26 h / ...`, and its "Drift algorithm (exact)" (spec line 106 onward) has no docs-equivalence step. E5's `touches` deliberately excludes the spec, so the implementer was right not to edit it — this is a plan-level gap for the orchestrator, not an implementer defect. **Fix:** In a later docs task (E8 or a follow-up), update the flake-check row and the drift algorithm in docs/superpowers/specs/2026-09-02-helm-design.md to D4's rule, or add a pointer there naming plan section D4 as the newer normative source.
- **minor** `pkgs/helm/collect.py:602` — `newest_covering()` short-circuits on the first match but in the miss case walks all 50 capped rows, and it is called twice (HEAD and live), so a worst case is ~100 `git diff --quiet` subprocesses per helm-collect run (every 5 minutes). Each is cheap and nothing caches a repeated (a,b) pair; `run()`'s 10 s timeout applies per call, so a cold/slow repo could push the tile to `unknown` by timeout rather than by a real verdict. No correctness impact today. **Fix:** Optional: memoise `_docs_equivalent` per collect run (a dict keyed on `frozenset({a, b})`), which also collapses the HEAD/live double walk when both share covering rows.
- **minor** `pkgs/helm/collect.py:530` — The defensive `isinstance(r.get("rev"), str)` filter in `_check_rows` is untested: mutation M6 (replacing it with `and True`) left all 131 tests green. Its absence would let a malformed row with a non-string `rev` reach `_docs_equivalent`, raising TypeError inside the tile and degrading it to status `unknown`. The guard is plan-specified and correct; it simply has no test. **Fix:** Optional: one row in tests/helm/test_collect.py writing `{"kind":"check","name":"flake-check","rev":null,"ok":true,...}` before a valid row and asserting the tile still reads `ok`.
