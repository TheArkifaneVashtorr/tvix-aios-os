## Findings

- **major** `tests/helm/test_collect.py:945` — vacuous-test: test_annotate_since_uses_first_row_of_current_run does not test the "current unbroken run" semantics it is named for. Its history is ok@08:00 → fail@09:00 → fail@11:00, in which "first row of the current unbroken run" and "earliest row anywhere with this verdict" are the same row, so the `break` at pkgs/helm/collect.py:754 — the only thing that makes the run *unbroken* — is unpinned. Mutating `break` -> `continue` leaves the whole suite green (136 passed). The behaviour that silently breaks is the user-visible claim on the page: a tile that flapped (fail → ok → fail) would report `since` from before the flap, i.e. the dashboard would overstate how long the tile has held its current verdict. Every other load-bearing behaviour in this task was killed by its test; this one is the single hole. (The plan prescribed this fixture verbatim, so this is a plan-level gap the implementer inherited rather than introduced — but nothing in the acceptance set catches it, so it is not merely hardening.) **Fix:** Add one flap row to the fixture so the older matching row is separated by a non-matching one, e.g. after the first record_status call insert `collect.record_status(cfg, _status_of({"drift": "fail", "gpu": "ok"}, t0), t0 - dt.timedelta(hours=2))` is not possible (append-only ordering), so instead extend forward: record ok/ok@08:00, fail/ok@09:00, ok/ok@10:00, fail/ok@11:00, fail/ok@12:00 and assert `by["drift"] == "2026-09-03T11:00:00Z"` (with `break`) — the mutant yields "2026-09-03T09:00:00Z" and the test goes red.
- **minor** `pkgs/helm/collect.py:691` — The mode of the new helm-status.jsonl is unpinned: mutating `os.fchmod(fd, 0o640)` to `0o644` keeps all 136 tests green. pkgs/evidence's equivalent append is pinned by test_append_creates_stream_with_envelope_and_mode, and the docstring at collect.py:685 claims the "same discipline as pkgs/evidence" — the discipline is copied but not proven. **Fix:** In test_record_status_writes_on_change_and_heartbeat_only add `assert stat.S_IMODE((tmp_path / "evidence" / "helm-status.jsonl").stat().st_mode) == 0o640`.
- **minor** `pkgs/helm/collect.py:758` — The plan's stated intent "a history failure never blocks the page" is defeated on one path. main() wraps record_status and annotate_since in try/except, but a bad `ts` in a helm-status row is copied verbatim into `t["since"]` by annotate_since without raising; the ValueError then surfaces later inside render_html's per-tile loop, which is unguarded (only the header's generated/next block has a try/except). Verified directly against HEAD: with a single row `{"kind":"helm-status","ts":"not-a-time","tiles":{"drift":"ok"}}` in the store, annotate_since yields `since = not-a-time` and `render_html` raises `ValueError: Invalid isoformat string: 'not-a-time'` — helm-collect would exit non-zero and leave the page stale on every subsequent run until the file is repaired. Low likelihood (the only writer is helm-collect itself, into a 0750 operator-owned dir, and a torn line is already skipped by _status_rows' JSONDecodeError guard), so this is robustness, not a live defect. **Fix:** Make _local total: `try: return _parse_iso(ts).astimezone().strftime("%H:%M %Z") except (ValueError, TypeError): return str(ts)` — the value is escaped by `esc()` either way, so the zero-outbound invariant is unaffected.
- **minor** `pkgs/helm/collect.py:919` — record_status/annotate_since are placed before the `--print` early return, so the read-only operator command `helm-status` (a wrapper for `helm-collect --print`, nixosModules/helm.nix) now appends verdict-history rows and can heartbeat the stream. The plan's wording ("after status = collect_all(cfg, now) and before writing") is ambiguous enough that this is defensible — the rows are true observations — but it means an interactive read command mutates the store, and hand runs interleave with the 5-minute collector's history. **Fix:** Either move both calls below `if args.do_print: … return 0`, or record the choice explicitly in docs/runbooks/helm.md so the operator knows `helm-status` writes history.
