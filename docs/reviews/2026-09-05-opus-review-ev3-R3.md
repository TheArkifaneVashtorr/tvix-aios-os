## Findings

- **major** `tests/helm/test_collect.py:320-370 (pkgs/helm/collect.py:164)` — The backup-parity tests do not pin WHICH unit or WHICH systemd scope the tile queries. They pass `fake_run({"journalctl": ..., "systemctl": _unit_show(...)})`, and `fake_run` matches on the argv prefix (argv[0] == "systemctl") only. Mutation M6 — rewriting line 164 to `_unit_result([], "not-a-real-unit.service")`, i.e. the wrong unit in the wrong scope — leaves all 143 tests green. The plan's Step 1 explicitly instructed the opposite: "key it on the tuple prefix (\"systemctl\", \"--user\", \"show\") and check argv[-1] in the fake". The implementer even wrote a helper that does this (`systemctl_fake`, test_collect.py:52) but used it only in the timer tests. A tile that silently reads some other unit's Result would report the wrong verdict for the exact failure this task exists to surface. **Fix:** Use `systemctl_fake({"proton-drive-push.service": _unit_show("exit-code", "1")})` (or add an assertion inside the fake that argv[:3] == ["systemctl", "--user", "show"] and argv[-1] == "proton-drive-push.service") in test_parity_unit_failure_beats_a_stale_ok_line and test_parity_unit_success_keeps_the_journal_verdict, so a wrong unit name or a missing --user turns the test red.
- **major** `pkgs/helm/collect.py:291-294` — The system-scope half of the timers feature has zero test coverage. Mutation M2 — deleting lines 291-294 outright (the `_unit_result([], service)` check for every `timers_system` entry) — leaves all 143 tests green. The plan's Interfaces say "for every audited timer, also `show -p Result -p ExecMainStatus <name>.service` on the matching service"; only the user-scope loop is pinned (test_timers_service_timeout_is_fail sets `cfg["timers_user"]`). This is live-relevant: `nixosModules/helm.nix:398-405` defaults `timers.system` to `["restic-backups-core-local.timer"]` when proton-backup is enabled, so a nightly restic backup killed by OOM or a timeout is exactly the case this untested branch is supposed to catch. **Fix:** Add a sibling of test_timers_service_timeout_is_fail with `cfg["timers_system"] = ["restic-backups-core-local.timer"]` whose fake answers the system-scope `.service` query with `_unit_show("oom-kill", "0")` and asserts the summary names `restic-backups-core-local.service` and `oom-kill`; make the fake reject a `--user` argv for the system-scope call so the scope is pinned too.
- **minor** `pkgs/helm/collect.py:165` — The `""` arm of `status not in ("0", "")` is unpinned (mutation M1 survives: dropping it leaves 143 green) and, as written, is close to unreachable — an empty ExecMainStatus only happens when systemctl produced no such line, in which case `result` is also "" and the first clause already fires. It is defensive code with neither a test nor a comment saying why. **Fix:** Either add a fixture with `_unit_show("success", "")` asserting the tile stays ok, or drop the `""` arm and say in the docstring that a missing Result line already reds the tile.
- **minor** `pkgs/helm/collect.py:316` — The timers summary prefix is still hard-coded `"not armed: "`, so a healthy, armed timer whose service failed renders as `not armed: helm-flake-check.service: timeout` — the tile says the timer is not armed when it is. The test only asserts substrings, so it does not catch the misstatement, and the runbook sentence added at docs/runbooks/helm.md:84-85 describes the two causes as distinct. **Fix:** Split the two offender kinds (e.g. `"not armed: " + ... ` and `"; failed: " + ...`, or a neutral prefix such as `"timers: "`), and assert the wording in the new test.
- **minor** `pkgs/helm/collect.py` — The plan's Files line lists `_TIMER_PROPS` and `_timer_armed` among the functions to modify; neither was touched. This is consistent with Step 3 (which specifies a separate `_unit_result` helper and a second `systemctl show`), so it is a design choice the plan itself sanctions rather than a real omission, but the FACTORY-RESULT declared no deviations at all and did not mention it. **Fix:** No code change needed; note it in the result so the plan's Files line can be corrected.
