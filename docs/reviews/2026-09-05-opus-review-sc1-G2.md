These must be byte-identical: the derived task graph detects a task as "landed" by matching `git log --format=%s` against the plan's subject (G1's `landed_subjects`), so as committed, G2 will never read as landed and the queue will keep re-offering it. **Fix (G2b):** a subject cannot be repaired by a follow-up commit, and amend is forbidden for the factory, so the fix round must produce **a single commit on a fresh branch cut from base `f1180c3`** that re-applies this exact diff and nothing else: `git checkout -b task/G2b f1180c3 && git cherry-pick -n cf75758`, then commit through `nix develop -c git commit -F <msgfile>` with the subject copied byte-for-byte from the plan (em dash and all), the same body, and the `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>` trailer. Verify with `git log -1 --format=%s | diff - <(printf '%s\n' '<the plan subject>')`.
- **major** `pkgs/evidence/repomap.py:44` (`flake_check_names`) — The 8-space indent anchor is the only thing keeping `let`-bound locals and nested attribute sets out of the check list, and no test detects its removal: relaxing the regex to any indent produces 86 names instead of 38 against the real `flake.nix` (M6). The plan's fixture cannot exercise it because its checks block contains no deeper-indented `name =` line. This matters immediately: G5 wires the check list into the `lint` gate, so an unproven extractor becomes a gate that can pass or fail for the wrong reason. **Fix (G2b):** strengthen the `FLAKE` fixture so the indent rule is load-bearing — give one check a nested attribute, e.g. change the `lint` entry to `        lint =\n          pkgs.runCommand "lint" {\n            nested = 5;\n          } "touch $out";` — and keep `test_flake_check_names_reads_the_checks_block_only` asserting the exact three-name list. - **minor** `pkgs/evidence/repomap.py:43` (`flake_check_names`) — The `break` on `      };` is inert on today's `flake.nix` (M1 returns the identical 38 names, because the checks block is the last multi-line output attribute), so the guard is a latent one for the day another 6-space output block with 8-space children lands after `checks`.
