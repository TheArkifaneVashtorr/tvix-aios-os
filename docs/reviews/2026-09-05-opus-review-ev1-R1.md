## Findings

- **major** `pkgs/broker/policy.py:266` — The CONNECT gate's keying on the routed host is untested. Reverting http_connect to flow.request.pretty_host (mutation M7) leaves all 49 broker tests and both VM checks green, yet that is precisely the r2-1-1 blocker on the HTTPS path: a client sending 'CONNECT denied.test:443 HTTP/1.1' with 'Host: allowed.test' would have the tunnel allowed on the strength of a client-supplied header. The plan's Interfaces line names the CONNECT gate explicitly ('Every policy decision (allowlist, CONNECT gate, credential injection, deny paths, body patch) keys on flow.request.host'), so this is a load-bearing behaviour with no test that can fail. The existing test_connect_denied_and_audited (tests/broker/test_policy.py:175) uses https_flow(), which sets no Host header. **Fix:** Add one unit test with a CONNECT-shaped flow whose Host header disagrees with the authority: build f = https_flow("denied.test"), set f.request.headers["Host"] = "allowed.test", call addon.http_connect(f), assert the 403 and reason 'connect-not-allowlisted'. Confirm it is red with flow.request.pretty_host and green with flow.request.host.
- **major** `pkgs/broker/policy.py:220` — The new third branch of _check - deny an allowlisted host whose TLS SNI disagrees with the routed destination - has no test. Deleting the whole branch (mutation M8) leaves all 49 tests green. This branch is new behaviour introduced by this commit (the pre-change file consulted the SNI only inside the not-allowlisted arm) and it is the only thing standing between a CONNECT to allowed.test and a TLS handshake to an attacker-chosen name; test_domain_fronting_denied_and_flagged (tests/broker/test_policy.py:158) covers only the not-allowlisted arm. **Fix:** Add test_allowlisted_host_with_mismatched_sni_is_denied: f = https_flow("allowed.test", sni="evil.test"); addon.request(f); assert 403 and audit reason == 'host/sni mismatch: sni=evil.test host=allowed.test'. It must fail when policy.py:220-222 is removed.
- **minor** `pkgs/broker/policy.py:204` — The Host-header comparison is exact-string, so it is case- and trailing-dot-sensitive. Verified against the pinned mitmproxy in the devShell: with flow.request.host == 'allowed.test', a header of 'Allowed.Test' yields pretty_host 'Allowed.Test' and 'allowed.test.' yields 'allowed.test.' - both denied with host-header-mismatch, while 'allowed.test:80' correctly matches. Hostnames are case-insensitive (RFC 3986 3.2.2, RFC 9110 4.2.3), so a well-behaved client that capitalises its Host header is refused. The failure is closed, not open, and today's clients (seat, lane) send lowercase - hence minor - but it is an availability trap that will read as a broker bug when it fires. **Fix:** Compare normalised names: claimed = flow.request.pretty_host.rstrip('.').casefold() against host = flow.request.host.rstrip('.').casefold(), keeping the raw values for the audit row and the reason string. Pin it by extending test_matching_host_header_with_port_is_allowed_and_injected into a parametrised case over ['allowed.test', 'Allowed.Test', 'allowed.test:80', 'ALLOWED.TEST'].
- **minor** `pkgs/broker/policy.py:278` — Fail-open asymmetry on a non-normalizable path. _denied_path fails closed (path-not-normalizable -> 403), but _patch_spec (policy.py:278) and _inject (policy.py:260) treat _prefix_match(...) is None as 'no match': a request whose path still carries a % after one decode is forwarded to a body_patch host WITHOUT the ZDR merge and without the credential, and the requestheaders streamed-body guard (policy.py:320) does not fire either. That contradicts the task's own fail-closed theme ('the data policy fails closed', policy.py:326). Exploitability is low - reaching /api/v1/chat/completions upstream while keeping a surviving % requires the upstream to double-decode - hence minor. The plan specified the None handling for inject ('no-match for inject') but left body_patch unspecified, so this is an open design point, not a spec violation. **Fix:** Either deny when the host has a body_patch entry and _prefix_match returns None (mirroring _denied_path), or record the asymmetry as an explicit gap row in docs/ledger/claims.toml when E2 lands. Either way pin it with a case at ('/api/v1/chat/completions%252f', application/json body) asserting the intended verdict.
- **minor** `pkgs/broker/policy.py:352` — The reorder the plan asked for ('_patch_body runs before _inject, so a denied body never carries the credential') is implemented and commented but not pinned: deleting the guard at policy.py:356-357 leaves all 49 tests green (mutation M5), because test_body_patch_fails_closed_when_it_cannot_patch configures no `inject` block. In production the consequence is nil - requestheaders() has already injected by then and the killed/403'd flow never reaches upstream - so this is defense-in-depth only. **Fix:** Add an `inject` entry to the fail-closed test's policy and assert `"Authorization" not in f.request.headers` on the denied branch, mirroring test_host_header_cannot_redirect_the_credential.
