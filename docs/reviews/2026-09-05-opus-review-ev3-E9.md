## Findings

- **major** `tests/evidence/test_evidence.py:421` — Vacuous coverage of the task's flagship rule (D4 docs-equivalence). Replacing `_docs_equivalent` (pkgs/evidence/evidence.py:123) with `return True` leaves all 24 tests green. The only assertion is the positive one — `assert b['checks']['flake-check']['head']['ok'] is True  # docs-equivalent coverage` — and `docs_only_ahead is True` at :414. Nothing asserts that a revision differing in CODE is NOT covered, so the bundle could report a stale observation as covering HEAD (a false green on exactly the fact a fresh session trusts) and no test would notice. Per the plan's own TDD constraint this is a vacuous-test major. The implementation itself is correct — this is a coverage hole, not a behaviour bug. **Fix:** Extend make_repo (tests/evidence/test_evidence.py:319) with a third commit that edits `flake.nix` (code, not docs) and return that as `head`; keep `live` at the first commit. Then assert both directions in test_bundle_reports_...: `assert b['docs_only_ahead'] is False` and, for a check recorded at `live`, `assert b['checks'][name]['head'] is None` while `b['checks'][name]['live']['ok'] is True`. Keep the existing docs-only case as a second repo/second test so the positive stays pinned.
- **major** `tests/evidence/test_evidence.py:427` — Single-row fixtures leave two ordering behaviours named in the commit subject unpinned. (a) Deleting the entire helm `since` walk-back loop (pkgs/evidence/evidence.py:189-193) so every tile reports `since = last['ts']` keeps 24 tests green — 'Helm since-when' can never be wrong because only one helm-status row is written. (b) Inverting the observation sort (`reverse=True`, evidence.py:167) or making `cover` take the oldest match (`for r in mine`, evidence.py:169) also keeps 24 tests green — newest-wins in `cover` is untested (E1's newest-wins test covers `latest_check`, a different function). **Fix:** In test_bundle_reports_...: append three helm-status rows — drift 'ok' @07:00, drift 'fail' @08:00, drift 'fail' @09:00 — and assert `b['helm']['tiles']['drift'] == {'status': 'fail', 'since': '2026-09-05T08:00:00Z'}` (the start of the unbroken run, not the newest row). Separately append two `flake-check` rows at the same rev, ok=False @08:00 then ok=True @09:00, and assert `b['checks']['flake-check']['head']['ts'] == '...T09:00:00Z'`.
- **minor** `README.md:16` — The rewrite dropped the file's trailing newline: HEAD~1:README.md ends `y ) . \n`, HEAD ends `y ) .` with no newline (git records '\ No newline at end of file'). treefmt does not format Markdown here so lint stays green, but the file is now POSIX-malformed and will produce a spurious one-line diff on the next edit. **Fix:** Re-add the trailing newline to README.md.
- **minor** `pkgs/evidence/evidence.py:146` — `.removesuffix('-dirty')` on the live revision is untested — deleting it keeps 24 tests green. A dirty live system would then fail REV_RE and report `live.rev = null`, silently blanking every 'live' check cell in the bundle. **Fix:** Add a one-line case using fake_nixos_version(tmp_path, live + '-dirty') and assert `b['live']['rev'] == live`.
- **minor** `pkgs/evidence/evidence.py:110` — `run()` uses timeout=20.0 but no caller handles `subprocess.TimeoutExpired`: `_git` catches only FileNotFoundError (evidence.py:117-121) and the nixos-version call catches `(FileNotFoundError, OSError)` (evidence.py:148) — TimeoutExpired is a SubprocessError, not an OSError. A hung git (e.g. an index.lock on a sibling repo) crashes `evidence bundle` with a traceback instead of degrading to 'unreadable'. This is the plan's own code copied verbatim, so it is not a deviation. **Fix:** Widen the excepts to `(OSError, subprocess.SubprocessError)` in `_git`, `_docs_equivalent` and the nixos-version block, or raise it as a follow-up gap row in claims.toml.
- **minor** `tests/evidence/test_evidence.py:461` — test_cli_bundle_markdown passes --repo but not --sibling, so the CLI falls back to globbing `~/flakes/*` and shells out to git in whatever repos the caller happens to have. It is hermetic under the check (flake.nix sets HOME=$TMPDIR), but a devShell run reads the operator's real trees and makes the test's runtime host-dependent. **Fix:** Pass `--sibling <repo>` (or `--sibling` pointing at an empty tmp dir) in the CLI test so the default glob is never exercised against the host.
