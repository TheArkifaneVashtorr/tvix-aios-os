## Findings

- **minor** `pkgs/helm/collect.py:934` — Moving record_status below the `--print` early return also reordered it relative to annotate_since (E6 recorded first, then annotated; E6b annotates at line 934, records at line 947). On the run where a verdict changes, annotate_since therefore no longer sees the row it is about to write, falls through to the `since = status["generated_at"]` default, and status.json carries a differently shaped RFC3339 value than on every following run. Probed directly against HEAD with two consecutive write-path main() calls on a temp config: run1 since: 2026-09-05T15:48:01.278350+00:00 / run2 since: 2026-09-05T15:48:01Z / row ts: 2026-09-05T15:48:01Z. Same instant, two shapes in one field. The plan's Interfaces line says since is the ts of the first row of the current run "or generated_at when the stream is empty" — after this reorder a change-run yields generated_at with a non-empty stream. Impact is cosmetic today: the only consumers are collect.py's own render_html/render_text, both of which go through _local, and grep confirms no .mjs/.py/.html consumer reads `since`. No check pins the field's shape either way. **Fix:** Either record before annotating on the write path (`if not args.do_print: record_status(...)` placed before the annotate_since block), or normalise the fallback to the same second-precision Z form record_status writes (`now.strftime("%Y-%m-%dT%H:%M:%SZ")`), and add one assertion on main()'s write-path status.json `since` so the shape is pinned.
- **minor** `pkgs/helm/collect.py:947` — The new test pins only half of the moved call. test_print_does_not_write_history proves record_status is NOT reached on the --print path; nothing proves it IS reached on the write path — deleting the entire try/except block at collect.py:944-949 leaves all 138 tests green (mutation 6 above). `grep -n 'collect.main(' tests/helm/test_collect.py` returns exactly one call site, line 1059, and it passes --print. A future edit that drops or strands the call would silently stop the verdict history and degrade every tile's `since` to generated_at forever, with helm-unit and lint both green. This is inherited scope rather than a regression (the same deletion also went unnoticed under E6), and it is covered by observation not assertion: helm-vm's log shows 'helm-collect: history: [Errno 30] Read-only file system: /var/lib/evidence' from the write-path run. **Fix:** Add a sibling to test_print_does_not_write_history that calls collect.main(["--config", cfg_path]) with the same fakes and an --out under tmp_path, then asserts (tmp_path/"evidence"/"helm-status.jsonl") exists and its single row has kind=="helm-status" and reason=="change".
