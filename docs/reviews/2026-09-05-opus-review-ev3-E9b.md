## Findings

- **minor** `pkgs/evidence/evidence.py:130` — The third of the three widened excepts is unfalsifiable. `_docs_equivalent`'s new `except (OSError, subprocess.SubprocessError): return False` has no test: mutating it to `raise` leaves all 27 tests green (mutation M9). The prescribed test, `test_bundle_hung_git_degrades_to_unreadable` (tests/evidence/test_evidence.py:521), monkeypatches `run` to raise for every call, which makes `head` None — so `docs_only = bool(head and live and _docs_equivalent(...))` (evidence.py:158) short-circuits before reaching it — and passes an empty store, so `cover()` never calls it either. The other two widened excepts (`_git`, the nixos-version block) are properly pinned. In a round whose whole purpose was closing vacuity holes, this is one new line of defensive code with no falsifying case. Consequence is bounded: without the guard a hung git during the docs-equivalence diff crashes `evidence bundle` with a traceback (the exact E9 minor), and with it the answer degrades conservatively to 'not covered', so no wrong fact can be reported either way. **Fix:** Either add a two-line direct test — monkeypatch `ev.run` to raise `subprocess.TimeoutExpired` and assert `ev._docs_equivalent(repo, rev_a, rev_b) is False` — or extend test_bundle_hung_git_degrades_to_unreadable so `boom` raises only when `'diff' in argv`, leaving `rev-parse`/`status` real and recording one check row so `cover()` runs, then assert `b['checks'][name]['head'] is None`. Fold into the next evidence follow-up; do not re-open E9b for it.
- **minor** `pkgs/evidence/evidence.py:145` — Undeclared widening of the bundle contract: `dirty` changed from `bool` to `bool | None` (`status = _git(repo, 'status', '--porcelain'); dirty = None if status is None else bool(status)`). The E9b prompt asked for `assert b['dirty'] is None`, which forces this, so it is sanctioned rather than a spec violation — but the FACTORY-RESULT declares no deviation and the commit body says only 'hung-git timeouts degrading to unreadable', not that the field gained a third value. It also changes behaviour outside the timeout case: a `--repo` that is not a git repo (git status exit 128 → `_git` returns None) now yields `dirty: null` where it yielded `false`. Nothing consumes the field except `render_bundle_markdown` (evidence.py:247), where None is falsy and the 'WORKING TREE DIRTY' marker simply stays off; I grepped the tree and no other Python, JS or Nix reads bundle's `dirty`. SCHEMA.md documents streams only, so no written contract contradicts it — but the plan's own bundle example (docs/superpowers/plans/2026-09-05-evidence-store.md:1642) still shows `"dirty": false`. **Fix:** No code change needed. When the plan's E9 interface block or docs/runbooks/evidence.md is next edited, say that `dirty` is `true | false | null` and that null means 'git could not be read'. Orchestrator note only.
