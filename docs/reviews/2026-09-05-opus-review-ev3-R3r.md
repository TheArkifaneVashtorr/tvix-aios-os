## Findings

- **major** `pkgs/helm/collect.py:165 (and tests/helm/test_collect.py, the deleted test_parity_empty_exec_status_is_ok)` — R3r's single code change leaves the ExecMainStatus half of the backup-parity guard completely unpinned. Deleting `or status != "0"` from `tile_backup_parity` (mutation MG1) leaves the suite at '145 passed' — no test in the repo exercises a `Result=success` with a non-zero (or empty) ExecMainStatus; `grep -rn ExecMainStatus` finds coverage only in the plan and the review, and the two parity tests that touch _unit_result use `_unit_show("exit-code", "1")` (killed by the `result != "success"` clause alone) and `_unit_show("success")`. R3's own Interfaces line requires '`Result` other than `success` (or a non-zero `ExecMainStatus`) -> `fail`', so this is a specified behaviour with zero test. R3r removed the only test that passed a status argument at all and added no replacement, and the net semantic change it made (empty status now reds the tile) is likewise unobserved: reverting line 165 to `status not in ("0", "")` keeps all 145 green. This is the exact vacuous-test class the A1 fix round exists to close, and the plan authored the gap (Step 3 orders the deletion and orders no replacement), so it is inherited rather than invented — but the branch ships it. **Fix:** Add one parity test next to test_parity_unit_success_keeps_the_journal_verdict: same journal fake, `systemctl_fake({"proton-drive-push.service": _unit_show("success", "1")}, scope="user")`, assert the tile is 'fail'. I ran exactly that against HEAD in the clone and it passes (and MG1 reds it), so it is a green-on-correct, red-on-mutant pin. If instead the team holds that Result=success always implies ExecMainStatus=0, then delete the `or status != "0"` clause entirely rather than keep an untestable guard, and say so in the docstring.
- **minor** `pkgs/helm/collect.py:258-261` — The new docstring asserts an empirical result — 'probed on core: a never-run unit and a non-existent unit both print `Result=success` / `ExecMainStatus=0`' — but nothing on the branch records that probe.
