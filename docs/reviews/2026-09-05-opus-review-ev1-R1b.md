## Findings

- **minor** `pkgs/broker/policy.py:348` — The guard added to requestheaders() (`if flow.response is not None or flow.error is not None: return` before `self._inject(flow)`) is dead in effect and untested: deleting it leaves all 56 broker tests green (mutation M5). The only way flow.response can be set at that point is _patch_spec's new path-not-normalizable denial — and in exactly that case _inject already returns without writing the header, because `_prefix_match(flow.request.path, paths)` on the same unnormalizable path yields None and `if not _prefix_match(...): return` fires. A probe driving addon.requestheaders() directly passes identically with and without the guard. **Fix:** Either drop the guard and keep the invariant where it is already enforced (a comment in _inject saying it fails closed on a non-normalizable path), or keep it and pin it with a test that drives addon.requestheaders() on a body_patch+inject host with '/api/v1/chat/completions%252f' AND makes _inject's own early return not the thing under test (e.g. also assert no audit row is written twice). As it stands the line is belt-and-braces on top of an already-closed door.
- **minor** `pkgs/broker/policy.py:274` — _patch_spec is now side-effecting: its name and `-> spec | None` contract read as a pure lookup, but it can now write flow.response / kill the flow via _deny_request. It is called twice per real flow (once from requestheaders, once from _patch_body via request()); the second call is only harmless because request() early-returns on an already-denied flow. A future caller that consults _patch_spec for a decision would silently deny. **Fix:** Rename to something that says it decides (e.g. _patch_spec_or_deny), or return a (spec, deny_reason) pair and let the two callers do the denying, mirroring _denied_path which returns a reason string rather than acting.
- **minor** `pkgs/broker/policy.py:208` — Case-insensitivity was applied only to the Host-header comparison; the allowlist test one line below still keys on the raw `flow.request.host` (`if host not in self.allow`) and the SNI comparison stays case-sensitive. This is fail-closed (a capitalised routed host or SNI denies rather than passes), so it is not a bypass, but the three comparisons of the same hostname now use two different notions of equality. **Fix:** Out of R1b's scope; worth a line in the R2/next round or a comment in _check recording that the allowlist and SNI comparisons are deliberately left exact-match because loosening them can only widen what is allowed.
