## Findings

- **major** `tools/factory/seat/factory-integrate:131-143 (test gap in tests/unit/80-seat-driver.bats:99-122)` — The only new test drives the `FACTORY_CHECK_CMD`/`custom` branch. The `nix build` loop — the branch that actually runs for this repo and that the plan's Interfaces call out first ("Produces one `checks` row per check run against `integ/<run>`'s head") — has no coverage at all. Mutation M6 replaced line 137 with `factory_record_check BOGUS deadbeef fail "$dur"` (wrong check name, a rev that is not even 40 hex, and the wrong verdict) and the suite stayed green: `ok 1 factory-integrate records one check observation per check it runs, at the integration head`. A wrong name or rev on the production path would ship silently and would then poison Helm's flake-check tile and `evidence bundle`, which are exactly what E7 exists to feed. **Fix:** Add one bats case that exercises the loop by shadowing `nix` on PATH, e.g. `mkdir -p "$BATS_TEST_TMPDIR/bin"; printf '#!%s\nexit 0\n' "$REAL_BASH" >"$BATS_TEST_TMPDIR/bin/nix"; chmod +x "$BATS_TEST_TMPDIR/bin/nix"` and run factory-integrate with `PATH="$BATS_TEST_TMPDIR/bin:$PATH"` and FACTORY_CHECK_CMD unset; assert the recorder log holds exactly two lines, `--name lint` and `--name unit`, both `--rev $(git -C "$root/base/src" rev-parse integ/r1) --ok --class nix-check --src seat-integrate`. That kills M6 and pins the `$chk`/`$head` wiring.
- **minor** `tools/factory/seat/factory-lib.sh:58-68` — The plan's Interfaces state the helper "never fails the caller (a recording failure is logged, the check verdict stands)", but nothing tests it: mutation M7 (deleting both `|| factory_log …` guards) leaves the suite green, because the test's recorder stub always exits 0. I confirmed the behaviour is correct out of band — with a stub that `exit 7`, factory-integrate still exits 0 and logs `factory-integrate: evidence: could not record custom@804fb6cb… (7)` — so this is test strength, not a defect. **Fix:** In the same bats file, re-run factory-integrate with a `FACTORY_EVIDENCE_CMD` stub that exits non-zero and assert `[ "$status" -eq 0 ]` plus a stderr line matching `evidence: could not record custom@`.
- **minor** `tools/factory/seat/factory-lib.sh:63,66` — The recorder's stdout is not redirected, so on the real path the evidence CLI's JSON row lands in factory-integrate's operator-facing stdout summary rather than in runs/<run>/integrate.log. Observed in an end-to-end probe: the line `{"class": "nix-check", …, "name": "custom", "ok": false, …}` appears between `CHECK custom fail` and `=== summary ===`. Every other side channel in this script goes to `$log` via `logonly`/`>>"$log"`. Nothing parses that stdout today (dark-factory.js does not call factory-integrate), so it is noise, not breakage. **Fix:** Append `>>"${log:-/dev/null}"` (stdout only — do not touch stderr, and never `2>/dev/null`) to both recorder invocations, or have factory_record_check swallow stdout with `>/dev/null` and let the log keep the `CHECK <name> pass|fail` line.
- **minor** `tools/factory/seat/factory-integrate:152` — The summary still recomputes the head with `logboth "head: $(git -C "$base" rev-parse integ/"$run")"` instead of printing the `$head` computed at line 95 and used for every observation. If the two ever diverged (a concurrent base refresh moving integ/<run> mid-run), the operator would read a head that no observation names. **Fix:** Change line 152 to `logboth "head: $head"` so the printed head is provably the one the observations carry.
- **minor** `tools/factory/seat/factory-lib.sh:59-60` — `local … flag=--fail` then `[ "$verdict" = ok ] && flag=--ok` means any third argument that is not the literal `ok` — including a typo or an empty string — is silently recorded as a failed check. The documented contract is `ok|fail`, so a mis-spelled verdict turns a green check into recorded evidence of a red one. **Fix:** Reject anything outside the contract: `case $verdict in ok) flag=--ok;; fail) flag=--fail;; *) factory_log "evidence: bad verdict $verdict for $name@$rev"; return 0;; esac`.
