### Field bugs after first acceptance run (2026-09-02, docs/research-2026-09-02-cowork-sending-hang.md)

Operator ran the gate; the Cowork window sent a message that stayed at
"Sending…" forever. Root-caused and fixed by the field-fix round (plan
`docs/superpowers/plans/2026-09-02-phase4b-cowork-sending-hang.md`), one
rebuild's worth of bugs, each with a code-level citation in the plan/digest:

12. **`downloads.claude.ai` denied by the broker → the Cowork VM image never
    downloads → "Sending…" forever.** [root cause] The VM's rootfs isn't
    shipped in the .deb; it's fetched on first session start. Fixed:
    allowlisted in both `services.egress-broker.instances.cowork.allow` and
    `claude-managed-settings.allowedDomains`.
13. **The broker's CA wasn't in the guest's trust path**, so once the
    download was allowed, TLS to the broker inside the VM would still have
    failed. Fixed: a `ca-bundle.crt` overlay scoped to `cowork.service`'s
    mount namespace (never host-wide).
14. **mitmproxy buffered SSE and large response bodies** by default —
    Claude Code's streaming watchdog aborts a silent stream, and a buffered
    1.3 GB download shows zero progress the whole time. Fixed: broker
    streams `text/event-stream` and bodies over `stream_large_bodies`.
15. **`nologin` as the `claude-app` user's `$SHELL`** broke the app's own
    environment-resolution step (`$SHELL -l -i -c env`). Fixed: `SHELL=/bin/sh`
    for `cowork.service`.
16. **The in-bubble Chromium hit a glibc mismatch** (the Electron wrapper's
    `LD_LIBRARY_PATH` leaked claude-desktop's newer glibc world into the host
    `chromium`). Fixed: `env -u LD_LIBRARY_PATH` in the `chromium-browser`
    wrapper.

17. **The desktop spawns its downloaded, generic-Linux Claude Code harness
    ON THE HOST** (the VM is a separate sandbox); NixOS refused it ("Could
    not start dynamically linked executable", exit 127, "Claude Code
    crashed"). Fixed: `programs.nix-ld` declared by cowork.nix; the exact
    binary verified to run through glibc's real loader before enabling.
18. **The upstream module put the proxied app (and its launcher) in the
    system profile**; the operator started a second instance on the host
    from the GNOME menu (ERR_CERT_AUTHORITY_INVALID: proxied, no broker CA,
    outside the netns). Fixed: the module gets `pkgs.emptyDirectory`;
    only `cowork.service` runs the app. Launch = `tools/cowork-up.sh`.
