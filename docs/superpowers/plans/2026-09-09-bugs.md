# Bugs — a standing plan (opened 2026-09-09)

> **For agentic workers:** Steps use checkbox (`- [ ]`) syntax. The seat driver composes each section into a brief; a seat sees only §Global Constraints, §Assumptions and its own section.

**Goal:** a home for defects found in landed, switched code — the things no plan owns. Operator decision 2026-09-09 ~06:00: **a bug's context is gathered by DeepSeek Flash agents, and the fix is written by a DeepSeek Pro agent.** That shape needs no new tooling: `docs/ledger/routing.toml` already routes `implement/docs/any` to `deepseek/deepseek-v4-flash` (effort off) and `implement/code/*` to `deepseek/deepseek-v4-pro-0813`, so a gather stage typed `(docs, …)` lands on Flash and a fix stage typed `(code, …)` lands on Pro, each Opus-gated like any other task.

**Why this plan exists.** `docs/ledger/plan-defects.toml` records PLAN defects, and it is keyed on gate rejections — a defect only appears there if a task was rejected for it. Nothing tracked a bug found in code that had already landed, been approved and been switched. The session of 2026-09-08 found roughly ten such defects and every one of them existed only as a sentence in a review file or a transcript.

**The two-stage shape, and why the fix stage is typed late.** A bug's `touches` cannot be honestly declared before anyone has read the code: the whole point is that nobody yet knows where the defect lives. So each bug is a pair. `<KEY>a (docs, …)` is the gather stage — a Flash agent reads, measures and writes a findings file; it changes no behaviour. `<KEY>b (code, …)` is the fix, typed by the orchestrator FROM the landed findings, exactly as a fix round is typed from a rejecting review. Typing `<KEY>b` before `<KEY>a` lands would be guessing, and this record is full of what guessing costs.

## Global Constraints

- Every rule of the house applies unchanged: brief §3 invariants, one commit per task, the subject `<area>: summary (test: <check names>)` with both trailers, red before green, every assertion killed by a named mutant, nothing outside `touches` without a disclosed Deviation line.
- **A gather stage changes no behaviour.** It may add a findings document and nothing else. It never edits a module, a package, a test or a check. If the fix looks obvious while gathering, the finding says so; it does not apply it.
- **A gather stage measures rather than reasons.** Every claim in a findings file carries the command that produced it and that command's real output. A claim without a command is a guess and must be labelled one.
- Nothing leaves the machine but the model call. No seat runs a switch, a `systemctl start/stop`, or a seat launch.

**What the orchestrator already measured — do not redo these, build on them:**

- `pkgs/dsh-openrouter/dsh-openrouter.sh:45-46` (the wrapper's own usage text) says the browser UI is where "dsh prints the token URL and opens it". So the authenticated URL carries a token this construction cannot know.
- `pkgs/seat/seat-run.py:137` runs the harness with `subprocess.run(cmd, capture_output=True, …)`, which buffers stdout until the process exits. For a long-running web server that is the whole session, which is why the job directory holds `job.json` and `url.txt` and no `stdout.txt` at all while the unit is active.
- The token is not recoverable from outside: the seeded `DSH_HOME` (`/home/dalhaka/factory/drive/<stamp>.dsh-home`) holds `hooks.json`, `settings.yaml` and `.credentials.yaml`, and none contains a token.

**What this stage must establish, each with the command and its real output:**

2. **Whether the token can be pre-set or the auth disabled** for a namespace-bound listener — check the harness wrapper and `dsh`'s own flags and environment. A pre-set token would let `seat-run` keep publishing a URL it knows; if there is no such option, the fix must stream and parse.
3. **How to stream without breaking headless.** `seat-run` uses the SAME `subprocess.run(capture_output=True)` for headless jobs, where the buffered stdout is parsed afterwards for the `FACTORY-RESULT` block (`result.txt`).
