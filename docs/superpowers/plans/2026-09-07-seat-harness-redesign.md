## Decisions (judgement calls, each with the reason and the alternative)

- **D1 The hook's home is an excluded file inside the workspace, not a `core.hooksPath` directory.** Fact: `sed -n '759,761p' flake.nix` → `shellHook = ''` / `git config core.hooksPath githooks` / `'';` — every `nix develop -c git commit` (the only commit path the WORKSPACE RULES allow) resets the clone's `core.hooksPath` to `githooks`, so a driver-set path would be silently undone before the seat's first commit. `factory-ws` therefore writes the hook to `$ws/githooks/commit-msg` and its touches list to `$ws/.factory-touches`, both listed in `.git/info/exclude` beside `.factory-meta` (`sed -n '113,114p' tools/factory/seat/factory-ws` → `factory_write_meta "$ws" "$base_sha" "$base_branch"` / `printf '.factory-meta\n' >>"$ws/.git/info/exclude"`), and sets `core.hooksPath githooks` itself so a commit outside the devShell runs it too. The tree's `githooks/pre-commit` is chained by construction (it is the same directory). Alternative rejected: editing the shellHook to respect an existing value — a `flake.nix` edit that collides with SD5/SD6/SB6 and changes every developer's checkout for a seat-only need.
- **D2 Six tasks instead of the spec's two driver tasks.** The spec's §6 intro says "each surviving change is one task" and §6.2 groups 9 with 2; design §3 Step 3 says an M that needs a second commit is two tasks. Change 9 alone is S (SH2); change 2 is M (SH3); change 5's checks half is M (SH4) and its probes half is S (SH5); the report is two S tasks (SH1 before any change, SH6 after the fields exist). The order 9 → 2 → 5 is kept by `dependsOn`. Alternative: the spec's grouping — two M+ tasks of ~15 files each, one gate per pair, and a rejection on any one concern sends the whole pair to a fix round.
- **D3 No follow-up turn** (operator question 1; the fact is pasted there).
- **D4 The integrator keeps its own run, unchanged.** See the map row; nix's content-addressed source path is the cache the spec falls back to. Alternative: skip the build when `integ/<run>^{tree}` equals `task/<KEY>^{tree}` and re-record the task-head verdict at the integration head — a verdict recorded at a rev it was not run at, which E7's rule ("the integrator records what it ran") forbids.
- **D5 Demotion precedence when several fire on one `done`:** `checks-misreported` > `checks-unverifiable` > `touches-violation` > `probe-mismatch` > `probe-missing` (a red check outranks a scope slip; a scope slip outranks a probe). Every arm appends its own clause to `FACTORY-NOTES`, so nothing that fired is lost; `error_class` names the first. `verify-timeout` is printed only where the class would otherwise be `none`.
- **D6 A missing contract degrades to "no record", never to a lie.** A task with no `### KEY` section (an ad-hoc `FACTORY_TASK_TEXT` run) has no `touches`, no probes: the driver writes no `touches_extra:`/`probes_verified:` line and logs `touches: no contract for <KEY>`; the fence declares those fields nullable. A plan that names them and a toolbox that cannot read them is logged the same way — and tested.
- **D7 Test files:** new bats tests go to `tests/unit/94-seat-harness.bats` (created by SH2); `80-seat-driver.bats` is edited only where an existing assertion pins the behaviour a task changes (named in that task).
- **D8 The re-plan pins every path-list consumer by a rule, carries SH3b's commit whole, and changes no source line it cannot show red.** The SH3b tree is behaviourally correct at every site the sh2f gate reached (`docs/reviews/2026-09-07-opus-review-sh2f-SH3b.md`, Summary: "The code is right; nothing holds it there"); the chain failed twice on the same shape — a fixture list that stopped one spelling short (SH3: no glob in a body; SH3b: no glob in a path). ## Global Constraints

- **Build-only.** No `sudo`, no `nixos-rebuild`, no `systemctl start/stop/restart/enable`, no basket mount/teardown, no reading `/var/lib/secrets/*`, `~/.config/openrouter/key` or `~/.config/restic/password`. Never launch a seat (`tools/factory/seat/factory-task`, `factory-wave`, `factory-dispatch` without `--dry-run`, `seat-submit`, `dsh-openrouter`): every driver behaviour in this plan is tested with fakes on `PATH` (a fake `dsh-openrouter`, a fake `nix`, `FACTORY_EVIDENCE_CMD`, `FACTORY_PYTHON3_CMD`), the idiom `tests/unit/80-seat-driver.bats` already uses.
- Commits go through the devShell (`nix develop -c git commit -F <msgfile>`), exactly one commit on `task/<KEY>`; `git add` new files **before** any `nix build`; never `--no-verify`, never `2>/dev/null` a gated command. The commit subject is the section's `commit subject` byte for byte; the trailers are the WORKSPACE RULES' two lines.
- TDD: the failing check first, shown red, then green. A load-bearing test counts only once it has been shown to fail; a test that cannot fail is a `vacuous-test` major finding. Every table row below names the one-line mutant that turns it red; land the test, run it red, paste the red line in the commit body, then land the change. Every proxy names what it stands in for and its gap (`docs/decisions/2026-09-03-test-based-reality-amendments.md`).
- **`touches` is a contract.** A file outside the section's `touches` is a deviation: name it in the commit body on its own line as `Deviation: <path> — <reason>` (from SH3 on, the workspace's `githooks/commit-msg` prints that line for you and refuses the commit until it is there; the driver recomputes the same diff after you exit, so `--no-verify` changes nothing). Two files are always exempt: `docs/MAP.md` (regenerate it with `python3 pkgs/evidence/repomap.py --root . write` whenever you add a file) and the `<!-- tasks:begin -->…<!-- tasks:end -->` queue block of `docs/OPERATIONS.md`, which the pre-commit hook rewrites; never edit `docs/OPERATIONS.md` outside that block (the integrator refuses the branch).
- Bats: one `[ … ]` per line, never `] && [` (`tests/lint/bats-and-chain.sh` is part of `lint`); no test may exec a driver through its shebang — hand `"$REAL_BASH" "$SEAT/<script>"` as `80-seat-driver.bats` does (the sandbox has no `/usr/bin/env`); every test runs under `FACTORY_ROOT="$BATS_TEST_TMPDIR/factory"` and never touches `~/factory`. Bash in `tools/factory/seat/*` is shellchecked by name (extensionless) or by the `find tools -name '*.sh'` sweep (`.sh` files); a new `.sh` file needs no list edit.
- Python is stdlib only in `pkgs/evidence`; `ruff format` (88 columns) rewraps every block below — a reformatting-only difference from the plan text is not a deviation. Run `nix develop -c ruff format pkgs/evidence tests/evidence` after writing. Every enum arm you add to `pkgs/evidence/streams.py` is also added to `ENUM_ARMS` in `tests/evidence/test_streams_policy.py` (that literal is the pin: `test_enum_arms_literal_matches_declared` goes red on any drift) and to `pkgs/evidence/SCHEMA.md`'s table.
- The result block's exact form ends your final reply: `FACTORY-RESULT status=done|partial|failed` — a space and no colon (the extractor accepts only `^FACTORY-RESULT[[:space:]]+status=(done|partial|failed)`; anything else is a near miss, recorded as failed until SH2 lands and as `unreported` after it); `FACTORY-CHECKS <name>=<pass|fail|not-run> …` naming exactly the section's acceptance checks; `FACTORY-COMMITS <n>` equal to `git rev-list --count <base>..task/<KEY>`; `FACTORY-NOTES` one line, never a bare `ok`. Never copy the WORKSPACE RULES or the result template into a project file. A `done` with zero commits, or with a commit count that disagrees with the branch, is demoted to `failed` by the driver (CR3r).
- Interim sentences until the guard behind each lands (design §4 A5; the deterministic guards P11 landed — `FACTORY_PLAN` required, a board rewrite refused at integration, a near-miss recorded): `curl --noproxy '*'` for any loopback probe; a `nix build` that needs a file not yet tracked fails with "path … does not exist" — `git add` first; `checks.unit` skips the basket mount tests.
- Nix style: statix rejects `{ ... }:` headers; `hosts/core/hardware-configuration.nix` is exempt from formatting; nothing in this plan edits a `.nix` file. Claude agents never write inside `~/flakes/dsh-harness`; this plan touches only `~/nixos-agent-env`.
- No secrets in the repo; no fixture may quote a key, token or a path under `/var/lib/secrets`; every string the store ingests is fenced (`streams.SECRET_RE`).
