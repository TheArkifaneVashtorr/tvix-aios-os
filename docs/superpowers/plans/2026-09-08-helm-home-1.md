## Decisions (judgement calls, each with the reason and the alternative)

- **D1 Switch is offered by the host's entry, never by the declaration.** `services.helm.home.flakes[*].profile` (reviewed Nix, asserted a member of `control.profiles`) is what makes a card's Switch button exist; a facts-only card (no declaration) still offers Switch. Reason: `~/flakes/gaming` has no declaration yet and sibling adoption is outside this sub-project — gating Switch on the declaration would take the gaming switch away the day HH2 removes it from the page. The declaration's `offers.profiles` is checked for truth (HH4) and shown as text. Alternative: Switch only when both agree — a regression until every sibling adopts.
- **D2 The declaration is `<path>/helm.nix`, exported as `helm = import ./helm.nix;`.** A refresh proposal is then a diff of one plain file, and `nix eval --offline --json <path>#helm` reads it. Alternative: an inline attrset in `flake.nix` — every accepted card would rewrite the flake file.
- **D3 The checker decides at eval time and exposes its error list.** `lib.helmDeclarationErrors :: declaration -> flakeOutputs -> [string]` is pure; `lib.checkHelmDeclaration` returns an ok derivation when the list is empty and `throw`s the joined list otherwise. Reason: a negative check can compare the exact message (the agentunit check's shape), and `builtins.tryEval` catches a `throw`; a build-time failure could not be asserted from inside a check. Alternative: a derivation that fails at build — unfalsifiable from `checks`.
- **D4 `pkgs/helm-home` is stdlib-only except `app.py` and `probe.py`**, which alone import `gi`; every external process goes through an injectable `run(argv, cwd=None) -> (rc, stdout, stderr)`. Reason: `helm-home-unit` runs under plain `python3` + pytest with no display and no D-Bus, like `helm-unit`. Alternative: GTK in the model — untestable in the sandbox.
- **D5 The reversibility check compares two evaluations of core itself** through `mkCore` (HH3), from the day the module is imported disabled, and HH9 adds the host file to the "with" side. Alternative: a fixture system — proves the module, not the host.
- **D6 One package `helm-home` with several entry points** (`helm-home-probe` first, `helm-home-a11y` for the VMs, `helm-home` the app), sharing the app id `org.nixos_agent_env.HelmHome` so the shortcut grant the probe earns is the app's. Alternative: a throwaway script — its grant would not carry over.
- **D7 Autostart is an XDG autostart entry under `/etc/xdg/autostart`**, not a user unit. Reason: GNOME's session starts autostart entries with the session's environment (`WAYLAND_DISPLAY`, the session bus); a user unit only sees what the session imports. Alternative: `systemd.user.services` with `graphical-session.target` — one more measurement.
- **D8 The refresh job uses the lane's Tier-B model with `--class permitted`, and the model never sets `updated` or `writtenAgainst`** — `refresh.py` overwrites both after parsing and re-renders `helm.nix` canonically. Alternative: trust the reply — a wrong stamp is a wrong "changed since".
- **D9 The control VM keeps the root-driven switch as its activation proof** (the v1 plan's D4) and adds the session-less refusal as alice. Alternative: drop the switch from the VM — the specialisation activation would go unproven.
- **D10 A first card writes `helm.nix` only.** If the flake has no `helm` output yet, the card shows the one line to add (`helm = import ./helm.nix;`) — a reviewed edit in that repo. Alternative: the app edits a sibling's `flake.nix` — outside "one reviewed diff each" (D-H2).
- **D11 D-H3's pin fact is corrected, the measurement stands.** The host pin carries `xdg-desktop-portal-gnome` 50.0, not 48, and its portal file lists `org.freedesktop.impl.portal.GlobalShortcuts` (Assumption 2); whether the grant persists and the raise wins focus is still HH1's measurement, as the spec asks.
- **D12 Two switches** (question 1's default).
- **D13 The AT-SPI drive is measured on a spike before the app** (HH6), through a small CLI (`helm-home-a11y`) the VM proof reuses. Alternative: measure inside HH8 — an M-sized task carrying an unknown.
- **D14 The app makes no network call of its own**: `nix eval --offline`, `nix run --offline`, `nix flake show --offline`; the lane job is the only egress and it is the broker's. Alternative: a plain `nix run` that may substitute from the cache — the operator's preference is nothing leaving the machine.

## Global Constraints

- **Build-only.** No `sudo`, `nixos-rebuild`, `systemctl start/stop/restart/enable`, basket mount/teardown; no reading `/var/lib/secrets/*`, `~/.config/openrouter/key`, `~/.config/restic/password`. Never open a transcript, a seat log or a store body (`~/.claude/projects/**`, `~/factory/runs/*/*.log`, `/var/lib/evidence/*.jsonl`): the fixtures here are synthetic and are the contract. No network. Brief §3 invariant 3 binds: the app adds no egress path (D14); invariant 2: no key is read or copied anywhere; invariant 5: the home list and the polkit rule are Nix.
- Commits go through the devShell (`nix develop -c git commit -F <msgfile>`), exactly one commit on `task/<KEY>`; `git add` new files **before** any `nix build` (a flake sees tracked files only); never `--no-verify`, never `2>/dev/null` a gated command. The subject is the section's `commit subject` byte for byte; the trailers are the WORKSPACE RULES' two lines.
- TDD: the failing check first, shown red, then green; paste the red and the green line in the commit body. Every Tests row below names the one-line mutant that turns it red; a test that cannot fail is a `vacuous-test` major. Every proxy names what it stands in for and its gap (`docs/decisions/2026-09-03-test-based-reality-amendments.md`).
- **`touches` is a contract.** A file outside it is a deviation (`Deviation: <path> — <reason>` in the commit body); the integrator refuses an undisclosed extra. Exempt: `docs/MAP.md` (regenerate with `python3 pkgs/evidence/repomap.py --root . write` when you add a file or a check — the pre-commit hook refuses a stale map) and the queue block of `docs/OPERATIONS.md`; never edit `docs/OPERATIONS.md` outside that block.
- **A new check** is one attribute inside `checks.${system} = {` in `flake.nix`, its name at exactly eight spaces of indent (`^ {8}([a-z][a-z0-9-]*) =` is how `repomap.py` finds it), its build `nix build .#checks.x86_64-linux.<name> -L --no-link`; the regenerated `docs/MAP.md` lists it in the same commit.
- **Python.** `pkgs/helm-home/*.py` is stdlib only, except `app.py` and `probe.py` (they import `gi`; no test imports them); `pkgs/helm-home/refresh.py` may import `evidence` from `pkgs/evidence` (the package puts that directory on `PYTHONPATH`). `ruff format` (88 columns) rewraps every block below — a reformatting-only difference is not a deviation; run `nix develop -c ruff format <your files>`. HH1 adds `pkgs/helm-home tests/helm-home` to the ruff lists in `flake.nix` (the `lint` check) and `githooks/pre-commit`; after HH1 every new `.py` under those directories is covered.
- **Nix.** statix rejects `{ ... }:` headers (write `_:` or name the arguments); `nixfmt` formats every `.nix` (treefmt); `deadnix` refuses an unused binding. A negated grep in a `runCommand` script is `if grep …; then exit 1; fi`, never `! grep` (errexit-exempt — sd2/SD7's rejection).
- **Bats** (none planned here): one `[ … ]` per line, never `] && [`.
- **VM tests** run with KVM on core (`nix build .#checks.x86_64-linux.<name>`); a GNOME VM needs `virtualisation.memorySize = 3072` and `cores = 2`; every wait is a `wait_until_succeeds`/`wait_for_*`, never a bare `sleep` as an assertion.
- The result block ends your final reply: `FACTORY-RESULT status=done|partial|failed` (a space, no colon); `FACTORY-CHECKS <name>=<pass|fail|not-run> …` naming exactly the section's acceptance; `FACTORY-COMMITS <n>`; `FACTORY-NOTES` one line; one `FACTORY-PROBE <name>=<value>` line per probe the section names. Never copy the WORKSPACE RULES or the result template into a project file.
- Privacy over convenience: the app never reads a transcript, a session file or a store body; the refresh payload carries git subjects, check names and the store's `derived/tasks` fields named in HH10 — never a prompt, a reply, a path under `~/.claude`, or a key.
