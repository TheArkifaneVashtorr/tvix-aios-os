# Lane L round 1 — factory ledger + the OpenRouter lane — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Executor: `tools/factory/dark-factory.js` in nixos-agent-env (host `core`, build-only). T2–T3 land with wiring round 2's switch.

**Goal:** (1) every factory run's economics come from a machine-readable ledger built from the workflow transcripts already on disk, backfilled; (2) a DeepSeek V4 Flash lane exists behind the egress broker, key injected per host, so Tier B jobs and proving-grounds arms can run without any agent holding a credential.

**Spec:** `docs/superpowers/specs/2026-09-03-data-and-models-system-design.md` §3, §4, §6, §8; decision `docs/decisions/2026-09-03-openrouter-lane-permitted-transcripts.md`; digest `docs/research-2026-09-03-openrouter-deepseek.md`.

## Global Constraints
- Build-only; the operator switches (with wiring round 2). No agent, unit or script holds the OpenRouter key; the broker injects it. Requests always carry `provider.zdr=true` and `provider.data_collection="deny"`.
- `local-only` inputs are refused at build time (a lane is an agent with an egress class: the same assertion shape as `lib/mkAgent.nix`).
- Ledger files are data, not source: `~/strategy/ledger/` (already backed up); schemas and scripts live here under `tools/ledger/` with pytest.

### T1: `tools/ledger/factory.py` — extract, backfill, roll up
**T1 lands as N6 of `docs/superpowers/plans/2026-09-04-dsh-review-fix-round.md`** (the ledger extractor, extended to dsh usage events).
**Files:** `tools/ledger/factory.py`, `tools/ledger/schema.md`, `tests/ledger/test_factory.py` (fixtures: a trimmed real workflow dir with 2 agents), `flake.nix` (`checks.ledger-unit`; ruff scope += tools/ledger tests/ledger).
- Input: a workflow transcript dir (`journal.jsonl`, `agent-*.jsonl`, `agent-*.meta.json`). Output lines (JSONL, `v: 1`, `src`): `factory-runs.jsonl` {run_id, started, ended, plan, prefix, repo, tasks:[{key,status,commit,fix_rounds}], agents, output_tokens, input_tokens, cache_read, cache_write, thinking, wall_s}; `factory-agents.jsonl` {run_id, agent_id, label, role_model, model_id, tokens{…}, wall_s, tool_uses}; `factory-findings.jsonl` {run_id, task, round, severity, file, title, class?}. Tests: exact numbers from the fixture; idempotent (re-running does not duplicate lines — keyed by run_id/agent_id).
- `factory.py backfill <projects-dir>` scans every `subagents/workflows/wf_*` dir; `factory.py rollup --week` prints tokens per role and lane, fix rounds per task, wall clock; the board's economics line is generated by `factory.py board-line <run_id>`.
- Hook: dark-factory.js's verify step calls `factory.py extract <this run's dir>` (the transcript dir is known from the Workflow tool's result — passed via args `transcriptDir` when available; otherwise the orchestrator runs it after the run). Commit `ledger: factory runs, agents and findings from the workflow transcripts; backfill; weekly rollup (test: ledger-unit, lint)`.

### T2: broker instance `openrouter` + lane unit template (module)
**Files:** `nixosModules/modelLane.nix` (new: `services.model-lanes.<name>` = { host, model, keyFile, brokerInstance, allowedClasses = [ "permitted" ] }), `hosts/core/lanes.nix`, `hosts/core/default.nix` (import), `flake.nix` (`checks.lane-eval`, `checks.lane-assertion-negative`, `host-core`).
- The module declares `services.egress-broker.instances.openrouter = { hostAddress = "10.100.3.1"; namespaceAddress = "10.100.3.2"; listenPort = 3131; allow = [ "openrouter.ai" ]; inject."openrouter.ai".valueFile = keyFile; }`; tmpfiles `z /var/lib/secrets/openrouter-key 0440 root egress-broker -`; a system template unit `lane-openrouter@.service` (`NetworkNamespacePath=/run/netns/egress-openrouter`, `DynamicUser` + `SupplementaryGroups=lane`, `HTTPS_PROXY=http://10.100.3.1:3131`, `SSL_CERT_FILE`/`NIX_SSL_CERT_FILE` = the instance's `ca-bundle.crt`, hardened like the Helm units) that runs `lane-run %i`: reads `/var/lib/lanes/openrouter/jobs/%i.json` {class, model, messages|prompt, schema?, max_tokens}, refuses `class != permitted` at runtime as belt-and-braces, posts to `https://openrouter.ai/api/v1/chat/completions` with `provider: {zdr:true, data_collection:"deny"}`, writes `/var/lib/lanes/openrouter/results/%i.json` {output, usage, model, provider, ts} and appends one ledger line. Assertions: keyFile outside the store; allowedClasses ⊆ {permitted}; the instance's allow list is exactly the one host. Negative check: a lane declared with `allowedClasses = [ "local-only" ]` fails the build. Commit `lane: services.model-lanes — broker-injected OpenRouter lane, job/result spool, permitted-only assertion (test: lane-eval, lane-assertion-negative, host-core, lint)`.

### T3: the client, the first shadow jobs, the VM proof
**Files:** `pkgs/lane/lane-run.py`, `pkgs/lane/lane-submit.py` (operator/orchestrator CLI: `lane-submit --class permitted --model deepseek/deepseek-v4-flash --schema x.json < prompt` → job id; `lane-wait <id>`), `tests/lane/test_lane_run.py` (fake HTTP server asserting the request body carries the provider block and no Authorization header — the broker adds it), `tests/integration/lane-vm.nix` (`checks.lane-vm`: the real broker module + a fake `openrouter.ai` served inside the VM by a TLS endpoint with the instance CA, proving the header is injected by the broker and absent from the unit's environment and job file; a `local-only` job is refused), `tools/lane/jobs/` (job templates: `run-summary`, `findings-classify`, `repo-coherence` — the last one feeds the entire repo's docs + modules into one 1M-context request and asks for contradictions between runbooks and code, the class of defect the pre-switch audit found by hand). Commit `lane: client, three Tier B job templates, VM proof of broker-side injection (test: lane-unit, lane-vm, lint)`.

### T2b (follow-up, after the switch): free-tier routing as an explicit per-job choice
Operator addendum 2026-09-03 (decision doc): `services.model-lanes.<name>.dataPolicies` (allowed set, default `[ "zdr" ]`; core: `[ "zdr" "free-training-ok" ]`), `lane-submit --data-policy zdr|free-training-ok` (default zdr), `lane-run` sends `provider: { zdr: false, data_collection: "allow" }` only for `free-training-ok`, refuses it for any class other than `permitted`, and writes the policy used into the result and the ledger line; assertion: a lane allowing `free-training-ok` must have `allowedClasses == [ "permitted" ]`; unit test: request bodies differ exactly in the provider block. Docs: `lanes.md` gains the trade-off paragraph and the free-tier limits from the digest.
